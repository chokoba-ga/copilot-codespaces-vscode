# Event POS - 学校イベント専用 会計アプリ

工業祭・文化祭・体育祭・地域イベントなど、学校のあらゆる行事で使い回せる
POSレジ・会計管理アプリです。React + TypeScript + Supabase + Netlify で作られています。

プログラミングの知識がなくても、この手順書の通りに進めれば公開できます。
**二段階認証(2FA)は必須ではありません**（個人の無料プランでは任意です）。
所要時間の目安：**20〜30分**。

---

## 1. 全体の流れ

1. Supabaseプロジェクトを作る（無料・2FA不要）
2. データベースを準備する（SQLを1回貼り付けるだけ）
3. ログイン機能（メール／パスワード）を設定する
4. 最初の管理者アカウントを作る
5. Netlifyでこのアプリを公開する
6. 環境変数を設定する

---

## 2. Supabaseプロジェクトを作る

1. https://supabase.com/ を開き、「Start your project」→ GitHubアカウントまたは
   メールアドレスでサインアップ（2段階認証の設定は求められません）
2. 「New project」→ 組織を選ぶ（初回は自動作成されます）
3. プロジェクト名（例：`school-event-pos`）とデータベースパスワードを設定
   （このパスワードは今回の手順では使いませんが、忘れずに控えておいてください）
4. リージョンは `Northeast Asia (Tokyo)` を選択
5. 「Create new project」をクリックし、数分待つ

## 3. データベースを準備する（SQLを貼り付けるだけ）

1. 左メニューの「SQL Editor」を開く
2. 「New query」をクリック
3. このプロジェクトに含まれる `supabase/schema.sql` の中身を全部コピーして貼り付ける
4. 右下の「Run」をクリック（数秒で完了します）

これだけで、テーブル・権限（Row Level Security）・会計処理のロジック・
リアルタイム同期の設定がすべて完了します。

> エラーが出た場合は、貼り付けが途中で切れていないか確認してください。
> 再実行したい場合は、一度Supabaseプロジェクトを作り直すのが簡単です。

## 4. ログイン機能を確認する

Supabaseはプロジェクト作成時点で、メール／パスワードによるログイン機能が
最初から有効になっています。追加の設定は不要です。

（任意）左メニュー「Authentication」→「Sign In / Providers」で、
「Confirm email」をオフにしておくと、確認メールなしですぐにログインできる
ようになり、学校行事のような短期利用では扱いやすくなります。

## 5. アカウントを発行する

1. 左メニュー「Authentication」→「Users」→「Add user」→「Create new user」
2. 先生・会計担当者・スタッフのメールアドレスと仮パスワードを入力して作成
   （「Auto Confirm User」にチェックを入れると、確認メールなしですぐ使えます）
3. 生徒には作成したメールアドレス・パスワードを個別に伝えてください

新しく作成されたアカウントは、自動的に**閲覧者（viewer）**権限になります
（安全のため、自分で自分を管理者にすることはできない設計です）。

## 6. 最初の管理者アカウントを作る

1. 左メニュー「Table Editor」→ `profiles` テーブルを開く
2. 手順5で作った、自分のアカウントの行を探す（emailで判別できます）
3. `role`列の値を `viewer` から `admin` に書き換えて保存（Enterキーで確定）
4. これで、そのアカウントでログインすると管理者としてすべての機能が使えます
5. 以降のメンバーの権限変更（スタッフ・閲覧者への変更）は、
   アプリ内の「設定」タブ →「メンバー・権限管理」から行えます

## 7. APIキーを確認する

1. 左メニュー「Project Settings」（歯車アイコン）→「API」
2. 「Project URL」と「anon public」キーをメモしておく
   （このキーは公開しても安全な設計です。データはすべて手順3で設定した
   Row Level Securityによって保護されます）

## 8. Netlifyで公開する

### 方法A：GitHub経由（推奨・自動デプロイ）

1. このプロジェクトをGitHubリポジトリにアップロードする
2. https://app.netlify.com/ にログイン →「Add new site」→「Import an existing project」
3. GitHubリポジトリを選択
4. ビルド設定はそのままでOK（`netlify.toml` に設定済み）
   - Build command: `npm run build`
   - Publish directory: `dist`
5. 「Deploy site」の前に、次の「9. 環境変数を設定する」を先に行ってください

### 方法B：手元のフォルダを直接アップロード

1. このプロジェクトのフォルダで以下を実行してビルドする
   ```
   npm install
   npm run build
   ```
2. https://app.netlify.com/drop を開き、生成された `dist` フォルダを
   ドラッグ＆ドロップする
3. この方法の場合、環境変数はビルド前にローカルの `.env` ファイルに
   設定しておく必要があります（後述）

## 9. 環境変数を設定する

`.env.example` をコピーして `.env` という名前のファイルを作り、
手順7でメモした値を入力してください。

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Netlifyで「方法A」を使う場合は、Netlifyの管理画面
「Site configuration」→「Environment variables」に同じ内容を登録してから
再度デプロイしてください（`.env` ファイルはGitにコミットしないでください。
`.gitignore` に含まれているため誤って公開される心配はありません）。

## 使い方（現場での運用）

- **レジ担当（スタッフ）**：商品をタップ→数量を確認→「会計へ」→
  お預かり金額を入力（省略可）→「会計を確定する」。これだけです。
- **試食・ロスが出たとき**：レジ画面上部の「ロス・試食」ボタンから登録。
  売上には計上されず、在庫だけが減ります。
- **シフト交代**：ログインしたままの端末を渡すだけで、直前の状態から
  そのまま続けられます。誰がどの端末を使っても同じデータを見ています。
- **通信が不安定な会場でも**：会計・ロス・試食・支出の新規登録は、
  電波が切れても端末内に保存され、電波が戻ると自動的にサーバーへ送信されます
  （画面右上または上部にオフライン中の表示が出ます）。
- **間違えて会計してしまったとき**：管理者が「履歴」タブから該当の会計を
  探し、「取消する」を押す（在庫は自動的に元に戻ります。取消・返金の操作
  自体はネット接続が必要です）。
- **行事が終わったら**：「設定」タブ →「学校提出用PDFを作成する」で
  会計報告書を作成し、そのままダウンロードして提出できます。

## オフライン対応の仕組みについて（重要）

- 一度表示したデータ（商品一覧・売上・支出など）は端末内（IndexedDB）に
  保存されるため、電波が切れても直前の状態を見ることができます。
- **会計・ロス登録・支出の新規登録**は、オフライン中でも実行でき、
  在庫やダッシュボードにもその場で反映されます。裏側では「送信待ちキュー」
  に記録され、電波が戻ると自動的にサーバーへ送信されます。
- 一方、**会計の取消・返金・イベント設定・商品編集・支出の編集や削除**は、
  管理者がじっくり行う操作のため、あえてオフライン対応を省略し、
  ネット接続が必要な仕様にしています（レジでの販売という一番忙しい場面の
  安定性を優先した設計です）。
- 同じ商品を複数端末が同時にオフラインで売り切ってしまった場合など、
  ごく稀に在庫の食い違いが起きる可能性があります。その場合は、行事終了後に
  「履歴」タブと在庫数を見比べ、必要であれば管理者が「取消」機能で調整して
  ください。

## アーキテクチャ・今後の拡張について

- `src/lib/db/` にすべてのデータアクセスロジックを集約しています。
  QRコード決済・バーコードスキャン・レシート印刷などを追加する場合は、
  ここに新しい関数を追加し、`src/components/register/` にUIを追加する形で
  既存部分を壊さずに拡張できます。
- 会計処理（在庫チェック＋減算＋記録）は Postgres の関数（RPC、
  `supabase/schema.sql` の `submit_sale` など）としてサーバー側に実装して
  あり、複数端末が同時に同じ商品を売っても在庫が正しく整合するように
  なっています。
- 複数店舗・複数学校対応は、`events` テーブルに `organization_id` 列を
  追加し、RLSポリシーに条件を1つ足すだけで対応できます。
- 多言語化は `src/lib/utils.ts` の文言・各コンポーネントの日本語文字列を
  i18nライブラリ（例: react-i18next）に置き換えることで対応可能です。
- LINE通知・メール通知は、Supabaseの Database Webhooks や Edge Functions を
  使って `sales` / `expenses` テーブルへの書き込みをトリガーに送信する形で
  追加できます。

## ローカルでの開発

```bash
npm install
cp .env.example .env   # Supabaseの値を入力してください
npm run dev
```
